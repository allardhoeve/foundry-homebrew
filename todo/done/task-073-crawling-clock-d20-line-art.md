# Task 073: Take the Crawling Clock's d20 back to a line drawing

Independent of every other open task. Supersedes two earlier attempts at the same
problem, `worktree-task-073-crawling-clock-d20-teardown` and `worktree-d20-split`,
neither of which was merged.

## Goal

The die shipped in 1.6.0 drew twenty pencil-hatched facets on toothy paper. Getting that
look cost 42 KB of SVG string literals in a JS module, a 548-line generated stylesheet,
forty `feTurbulence` filters live at once, and a 582-line generator. This task replaces it
with a die made of twenty clipped triangles and nothing else, keeping the look the flat die
had in 1.4.0 and adding the one thing 1.4.0 could not do: it turns.

## Background

Two branches had already tried to tidy the pencil die and both grew rather than shrank.
The teardown branch found the two genuinely good ideas, but both were solutions to problems
the pencil look created:

- the 400-line lighting table is a dot product, `(Rv·n)·L = n·(Rv'·L)`
- twenty paper filters can be three, if the faces are 3-coloured

The split branch found the one real defect: geometry, numbering and artwork shared a single
random stream, so re-drawing the die silently moved which number sat on which face. Its
frozen `NUMBERING` is the only thing carried forward from either branch.

The conclusion both branches missed is that the pencil look was the cost. Removing it
removes the asset, the filters, the loader, the lighting and most of the generator at once.

## Design decisions (resolved)

| Question | Decision |
|----------|----------|
| Does the die turn? | Yes. This is the whole reason the geometry exists. |
| Keep the generator? | Yes, and mark its output clearly as generated. Every line of it does something that cannot be done by hand. |
| Facet appearance | A line drawing: no fill, no shading, no light. 1.4.0's look. |
| Ink direction | Parchment lines on the panel's own ground, as 1.4.0 had it. |
| The `stirs` state at 1 | The numerals turn red; the die keeps its colour. One red thing on the card, not two. |
| Hand-drawn wobble | Not reproduced. It is the one thing CSS cannot do, and chasing it is what produced the asset and the filters in the first place. |
| Numeral fitting table | Kept verbatim. It was measured against the facet geometry, which is unchanged. |

## Changes

### New: `tools/d20/d20.py`

Replaces `tools/d20/generate-d20.py` (582 lines, deleted). Solves the icosahedron, scales
it so its front face projects to the 49.3-unit facet the numeral fitting was measured
against, asserts the numbering, and builds each face's local frame.

Emits two files, both banner-marked `Generated by tools/d20/d20.py -- do not edit by hand`:

- `module/styles/crawling-clock-d20.css` — twenty face placements, twenty orientations
- `module/src/crawling-clock-d20.js` — the numbering and the range

No randomness, so the output is byte-identical across runs. Run with `npm run gen:d20`.

### Modified: `module/styles/crawling-clock.css`

The die's look. The facet is one rule: an even-odd `clip-path` leaving the ring between the
triangle and a copy inset a little way. Two things in it are load-bearing and neither is
obvious, so both are commented in place:

- Both triangles scale about the centroid. An equilateral triangle's centroid is also its
  incentre, so a uniform scale is a uniform inset and the line keeps its weight on all
  three sides.
- The plate is scaled to `1.06`, past its own facet, so the ring *straddles* the crease.
  Without that, two neighbouring facets each draw a line just inside a shared edge and
  every crease comes out doubled with a dark gap down the middle.

The `scale(1.06)` also throws a spike one line-width long past each vertex, five per
vertex. Kept deliberately: it reads as the die wobbling rather than as a drawing error, and
it is most visible mid-turn. The spikes and the single creases are the same knob and cannot
be separated without nesting a second element inside every facet.

Removed: the `@property` blocks, the Lambert dot product, the plate/hatch/edge ink rules,
and the numeral's light-dependent opacity.

### Modified: `module/src/crawling-clock.js`

`ccDieMarkup` maps over the values rather than over artwork, and emits a plate `div` where
the inline `<svg>` was. No fetch, no `DOMParser`, no promise cache, no async paint step.

### Modified: `tools/preview/crawling-clock.py`

Follows the new markup. `die_parts()` becomes `numbering()`, since there are no parts to
lift out of the JS any more.

## Tests

Rewrote `tests/unit/crawling-clock-d20.test.js`. Dropped the artwork and lighting-table
assertions, which no longer describe anything. Added one:

- `keeps the numbering it was fitted for` — pins the frozen array, so "do not move this"
  fails rather than drifts. This is the defect the split branch found.

Kept: twenty faces, 1-20 once each, the range covers the clock, every face has a transform,
every value has an orientation, every metric the hand-written stylesheet reads exists, and
every value has a numeral fitting entry.

## Verification

```bash
npm run test:unit
npm run gen:d20 && git diff --exit-code module/styles/crawling-clock-d20.css
npm run preview:clock && open docs/design/crawling-clock-values.html
```

**Results (2026-09-04):** 97 unit tests pass, up from 90. Generator output byte-identical
across two runs. Preview page rebuilt and inspected at all twenty values plus the low and
stirs states. The turn was driven in a real browser and captured frame by frame; the ease
front-loads, reaching most of the rotation inside 200ms of its 700ms and spending the rest
settling off the overshoot.
